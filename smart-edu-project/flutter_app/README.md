# تطبيق منارة المعرفة - Flutter

هذه نسخة Flutter أصلية مستقلة من منصة منارة المعرفة. تعمل ككود Dart وFlutter Widgets أصلي، بدون WebView أو طبقة واجهة ويب.

## التشغيل محلياً

```bash
flutter pub get
flutter run
```

الأهداف المدعومة: Android و iOS و iPadOS. يتطلب بناء iOS جهاز macOS مع Xcode.

## الهيكل

- `lib/models` نماذج الأدوار والدروس والتحديات والإنجازات.
- `lib/state` حالة التطبيق المشتركة (Provider) مع حفظ جلسة الدور.
- `lib/theme` نظام الألوان والثيم العربي.
- `lib/screens` اختيار الدور، التنقل الأصلي، لوحة الطالب، الألعاب ولوحات الأدوار.

## ما تم نقله في النواة الحالية

- اختيار الدور وتسجيل الدخول للأدوار الأربعة.
- حالة جلسة محلية قابلة للاستبدال بمصادقة Supabase.
- لوحة الطالب: XP، الجواهر، المستوى، Streak، الإنجازات والتحديات.
- مكتبة الدروس وتفاصيل الدرس ومكافأة الإكمال.
- اختبارات متعددة الأسئلة مع نتيجة ومكافآت.
- ألعاب تفاعلية أولية.
- مركز الفيديو.
- محادثة الصف.
- لوحات المعلم والمشرف وولي الأمر.
- حساب المستخدم وتسجيل الخروج.
- عقد بيانات مستقل ومستودع Supabase أصلي.
- تخزين محلي دائم للجلسة والتقدم والسجلات والرسائل.
- تخصيص avatar الطالب وحفظه محلياً.
- مشغل فيديو أصلي عبر `video_player`.
- تمرير مستودع Supabase إلى الحالة: تحميل فيديوهات الطالب وحفظ XP والجواهر عند توفر الاتصال.

للتجربة المحلية بدون Supabase:

| الدور | اسم المستخدم |
|---|---|
| الطالب | `salman` |
| المعلم | `ahmad` |
| ولي الأمر | `parent` |
| المشرف | `dekram` |

كلمة مرور المشرف التجريبية `123`، وكلمة المرور التجريبية لبقية الأدوار `123456`.
الحسابات المنشأة أو المحمّلة من Supabase تحتاج كلمة مرور مخزنة صحيحة؛ لا يتم قبول
حساب بلا كلمة مرور.

## ما تم نقله في إدارة الحسابات والقوائم

- شاشة إدارة حسابات واحدة للطلاب وأولياء الأمور.
- تبويبات الطلاب وأولياء الأمور مع البحث.
- إنشاء وتعديل وحذف الحسابات.
- ربط ولي الأمر بأكثر من طالب.
- حفظ بيانات ولي الأمر والأبناء محلياً.
- إدارة الاختبارات والصلاحيات وإعدادات النظام وإشعارات الفيديو.
- مركز الألعاب: الاختبار السريع، لعبة الذاكرة، وصح أو خطأ.
- تفاعل Avatar، الاجتماعات المباشرة، المؤثرات الصوتية، وحركات البطاقات.

## مهم عند التشغيل في Replit

سير العمل الموجود في جذر المشروع (`Start application`) يشغّل:

```bash
npm run dev
```

وهذا يعرض نسخة React القديمة في معاينة الويب. لا يشغّل Flutter ولا يحوّل النسخة القديمة تلقائياً إلى Flutter.

النسخة الأصلية الجديدة موجودة في `flutter_app/`، وتشغيلها يحتاج Flutter SDK:

```bash
cd flutter_app
flutter pub get
flutter run
```

لا يمكن تشغيل `flutter run` من بيئة المشروع الحالية لأن Flutter وDart غير مثبتين فيها. لذلك لا تعتبر معاينة `npm run dev` اختباراً لواجهة Flutter.

## إعداد Supabase

```bash
flutter run \
  --dart-define=SUPABASE_URL=https://your-project.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=your-anon-key \
  --dart-define=SUPABASE_VIDEO_BUCKET=lesson-videos
```

لا تضع المفاتيح داخل ملفات Dart أو Git.

### تخزين الفيديو الآمن

- أنشئ bucket باسم `lesson-videos` أو الاسم الذي تختاره، واجعله **خاصاً** وليس عاماً.
- لا يكفي وضع `SUPABASE_VIDEO_BUCKET` وحده؛ الرفع وإصدار Signed URLs يتطلبان
  جلسة Supabase Auth موثوقة (`client.auth.currentSession`).
- التطبيق الحالي يستخدم مصادقة المنصة المخصصة للأدوار، لذلك سيبقى رفع Storage
  معطلاً تلقائياً ما لم تتم إضافة جسر مصادقة Supabase Auth أو Edge Function
  موثوقة. هذا مقصود لمنع تسريب مفتاح anon أو فتح bucket خاص للزوار.
- عند تفعيل جسر المصادقة، يجب السماح للمستخدم الموثق برفع الملفات داخل مساره
  فقط، والسماح بالقراءة عبر Signed URLs فقط. لا تضف سياسة قراءة عامة.
- المسارات المخزنة في `lesson_configs.data.videoUrl` تكون مسارات داخل bucket،
  ويحوّلها التطبيق إلى رابط صالح لمدة ساعة عند التشغيل.
